08

Компилятор Simple в SML

  • проект к занятию 08
  • Python
  • компилятор

Симулятор из занятия 07 понимает только машинные команды. Напишите компилятор, который переводит программу на языке Simple в SML — и она выполнится на вашей собственной машине.

Что понадобится

Проект опирается на симулятор Simpletron из занятия 07 и его загрузчик SML из файла. Если симулятор ещё не готов, начните с него.

01 · simple

Язык Simple

Simple — учебный язык высокого уровня из книги Дейтелов (специальный раздел «Building Your Own Compiler»; в разных изданиях — упражнения 12.25–12.29 или 12.26–12.30). Он похож на ранний BASIC: семь команд, целые числа и переменные из одной буквы. Этого хватает для циклов и ветвлений, а компилятор переводит программу в SML.

Команды

Команды языка Simple
Команда Пример Смысл

Правила языка

  • Каждый оператор начинается с номера строки; номера идут по возрастанию.
  • Программа записывается строчными буквами.
  • Переменная — одна буква a…z. Все переменные целые и создаются при первом упоминании со значением 0.
  • Выражения целочисленные: +, -, *, /, скобки и обычный приоритет. По правилам книги операнды и операции отделяются пробелами.
  • В if допустимы сравнения <, >, <=, >=, == и !=.
  • Строк и массивов нет; повторение выражается через goto и if.

Память и адреса

Адреса распределяет компилятор: инструкции занимают ячейки с 00 вверх, а переменные, константы и временные ячейки — с 99 вниз. Номер строки тоже получает адрес: это адрес первой инструкции её оператора. На такие адреса ссылаются goto и if.

Компилятор должен следить за встречей счётчиков: если очередная инструкция должна лечь дальше, чем начинается область данных, памяти не хватило — сообщите об ошибке.

Условия

Отдельной команды сравнения в SML нет. Компилятор вычитает одно значение из другого и смотрит на знак результата: если a − b равно нулю, то a == b; если отрицательно, то a < b.

Как компилировать условия
Условие Последовательность SML
a == bLOAD a; SUBTRACT b; BRANCHZERO N
a < bLOAD a; SUBTRACT b; BRANCHNEG N
a <= bLOAD a; SUBTRACT b; BRANCHNEG N; BRANCHZERO N
a > bLOAD a; SUBTRACT b; BRANCHNEG S; BRANCHZERO S; BRANCH N; S:
a >= bLOAD a; SUBTRACT b; BRANCHNEG S; BRANCH N; S:
a != bLOAD a; SUBTRACT b; BRANCHZERO S; BRANCH N; S:

Здесь N — адрес строки из goto, а S — адрес команды сразу после проверки: на него переходят, чтобы пропустить ветку. Если строка N ещё не встречалась, её адрес неизвестен — все инструкции с такими операндами нужно запомнить и дополнить во втором проходе.

Помните про четырёхзначную арифметику: разность должна помещаться в диапазон -9999…+9999. Поэтому сравнивать числа, отличающиеся больше чем на 9999, на этой машине нельзя — будет переполнение аккумулятора. В книге контрольное значение равно -9999; для теста ниже мы берём -1, чтобы разность оставалась в пределах разрядной сетки.

Выражения в let

Выражение удобно переводить в два шага: сначала из инфиксной записи в постфиксную, затем из постфиксной — в SML.

  1. Переведите выражение в постфиксную запись стеком операторов (алгоритм сортировочной станции).
  2. Идите по постфиксной записи со стеком адресов. Переменная или константа — положите её адрес. Оператор — снимите два адреса, сгенерируйте LOAD left; OP right; STORE temp и положите адрес temp.
  3. В конце на стеке останется адрес результата: сгенерируйте LOAD result; STORE target.

Например, для let u = 4 * ( j - 56 ) постфиксная запись — 4 j 56 - *, а код получается такой:

LOAD j
SUBTRACT 56
STORE T1
LOAD 4
MULTIPLY T1
STORE T2
LOAD T2
STORE u

T1 и T2 — временные ячейки, которые компилятор выделяет из области данных. Пара STORE T2; LOAD T2 выглядит лишней; её можно убрать отдельным шагом оптимизации, но для первой версии компилятора важнее простота.

Два прохода

  1. Первый проход. Читайте строки, разбивайте их на слова и заполняйте таблицу символов: номер строки → адрес, переменная → адрес, константа → адрес. Сразу генерируйте инструкции. Если цель перехода ещё неизвестна, оставьте операнд 00 и запишите номер строки в список flags под адресом этой инструкции.
  2. Второй проход. Для каждой записи в flags найдите адрес строки в таблице символов и подставьте его в операнд. После этого выведите все инструкции в файл: по одной на строку в формате +dddd.

Полный пример

Программа из книги суммирует числа от 1 до x:

5 rem sum 1 to x
10 input x
15 rem check y == x
20 if y == x goto 60
25 rem increment y
30 let y = y + 1
35 rem add y to total
40 let t = t + y
45 rem loop y
50 goto 20
55 rem output result
60 print t
99 end

После двух проходов получается такой набор инструкций (адреса переменных: x — 99, y — 98, константа 1 — 97, t — 95, временные — 96 и 94):

+1099
+2098
+3199
+4215
+2098
+3097
+2196
+2096
+2198
+2095
+3098
+2194
+2094
+2195
+4001
+1195
+4300

Обратите внимание на инструкцию +4215: в первом проходе она была +4200, потому что строка 60 ещё не имела адреса; второй проход заменил операнд на 15.

Это только инструкции. В полном файле после них обязаны идти данные: нули до ячейки 96, затем +0001 в ячейке 97 (константа 1), +0000 в 98 (y) и +0000 в 99 (x). Если вывести одни инструкции, константа потеряется, ADD 97 будет прибавлять ноль, и цикл никогда не закончится. Запустите готовый файл в симуляторе с x = 3 — должно получиться +0006.

02 · компилятор

Компилятор: задание

Напишите компилятор simple.py, который читает файл на Simple и создаёт рядом файл SML. Готовый SML загружается в симулятор через загрузчик из проекта к занятию 07 — и программа на языке высокого уровня выполняется на вашей собственной машине.

Что должна делать программа

  1. Запуск. python simple.py sum.simple создаёт sum.sml. Если файла нет или в нём ошибка, компилятор печатает сообщение и не создаёт выходной файл.
  2. Разбор. Номера строк идут по возрастанию; команда — второе слово строки. Для if разбирайте шаблон if a OP b goto N, для let — имя, знак = и выражение.
  3. Таблица символов. Словарь symbols: ключ — пара «тип, имя» (например, ("L", 20), ("V", "x"), ("C", 1)), значение — адрес. Типы: L — строка, V — переменная, C — константа.
  4. Два прохода. Первый строит таблицу и инструкции, второй дополняет переходы вперёд и пишет файл. Для незавершённых переходов используйте словарь flags: адрес инструкции → номер строки.
  5. Полнота. Поддержите все семь команд, шесть сравнений, приоритет операций и скобки. Деление целочисленное.
  6. Ошибки. Неизвестная команда, номер строки не по возрастанию, кончилась память, неизвестная строка в goto, лишние слова — всё это должно давать понятное сообщение с номером строки.
  7. Формат результата. В файл выводятся все 100 слов памяти: сначала инструкции, затем нули и значения переменных и констант. Например, константа 1 попадёт в свою ячейку как +0001 — без этого команда ADD прибавляла бы ноль. Одна инструкция в строке, знак и четыре цифры: +1099. Такой файл читает загрузчик симулятора.
  8. Ограничения. Без классов и глобальных переменных. Состояние компилятора — словарь state с полями memory, symbols, flags, code и data; логика — функции.

Проверка

Скомпилируйте три программы и выполните полученные SML-файлы в симуляторе. Помните про область данных: константа 1 и контрольное значение -1 должны попасть в файл, иначе циклы не завершатся.

Сумма

10 rem сумма двух чисел
20 input a
30 input b
40 let c = a + b
50 print c
60 end

Ввод +12 и -5 → +0007.

Большее из двух

10 input s
20 input t
30 if s >= t goto 60
40 print t
50 goto 70
60 print s
70 end

Ввод +3 и +8 → +0008. Здесь проверка смотрит вперёд на строку 60, поэтому без второго прохода не обойтись.

Квадраты чисел

10 input j
20 if j == -1 goto 60
30 let k = j * j
40 print k
50 goto 10
60 end

Ввод +3, -4, -1 → +0009, +0016, затем остановка.

Критерии приёмки

  • Компилятор создаёт .sml с одной инструкцией +dddd в строке и областью данных — переменными и константами.
  • Симулятор из раздела 08 загружает этот файл и выполняет программу.
  • Работают все семь команд и все шесть сравнений.
  • Выражения считаются с учётом приоритета и скобок.
  • Переходы вперёд разрешаются вторым проходом.
  • Ошибки сообщаются с номером строки, выходной файл не создаётся.
  • Нет классов и глобальных переменных; состояние передаётся словарём.
03 · развитие

Если хочется большего

  • Оптимизировать компилятор: убирать пары STORE temp и LOAD temp, идущие подряд.
  • Разрешить input x, y и print a, b с несколькими переменными.
  • Добавить в Simple % и ^, а в SML — новые команды для них.
  • Сделать gosub/return, циклы for … next, массивы и строки.
  • Написать интерпретатор Simple — программу, которая выполняет операторы сразу, без компиляции в SML.
