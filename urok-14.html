Конспект

Массив и список

Массив хранит элементы подряд: доступ по индексу мгновенный, но вставка в середину требует сдвига. Связный список хранит элементы узлами со ссылками: вставка дешёвая, а поиск — последовательный.

Выбор зависит от того, что чаще: читать по номеру или менять структуру.

Стек и очередь

Стек работает по принципу «последний пришёл — первый вышел»: так устроены вызовы функций и отмена действий.

Очередь работает наоборот: «первый пришёл — первый вышел». Её используют для задач, печати и обработки событий.

Деревья и хеш-таблицы

Дерево поиска держит элементы упорядоченно и даёт логарифмический поиск. Хеш-таблица считает хеш ключа и обращается сразу к нужной ячейке — в среднем за постоянное время.

У хеш-таблиц есть цена: коллизии и отсутствие порядка. У деревьев — накладные расходы на балансировку.

Множества и словари: хеш-таблицы в Python

В Python хеш-таблицы лежат в основе dict и set. Словарь хранит пары «ключ → значение», а множество — только элементы-ключи. Проверка in, добавление и доступ по ключу в среднем работают за O(1): Python вычисляет хеш и идёт к нужной ячейке, не перебирая все элементы.

visited = set()
visited.add("A")            # добавить элемент
print("B" in visited)       # False — проверка в среднем O(1)

prices = {"хлеб": 60, "молоко": 90}
print(prices["хлеб"])       # 60 — доступ по ключу

Множество удобно для быстрых проверок «встречалось ли значение» и удаления дубликатов: set([3, 1, 3, 2]) даёт {1, 2, 3}. Порядок элементов множество не гарантирует. Ключи должны быть хешируемыми — например, числа, строки и кортежи из них. Список, словарь или множество ключом быть не может: их содержимое меняется, а хеш должен оставаться стабильным.

Словарь сохраняет порядок добавления ключей, но не сортирует их. Поиск всё равно идёт по хешу, поэтому чтобы получить ключи по алфавиту, словарь нужно дополнительно отсортировать.

Как находится хеш

Хеш-функция превращает ключ в целое число. Для чисел хеш часто совпадает с самим числом, для строки вычисляется по её символам, для кортежа — по хешам элементов. Хорошая хеш-функция работает быстро и распределяет ключи по таблице равномерно. В Python результат можно посмотреть функцией hash().

print(hash(42))         # 42
print(hash("кот"))      # целое число, зависит от запуска
print(hash((1, 2)))     # хеш кортежа

size = 8
print(hash(10) % size)  # 2
print(hash(18) % size)  # 2 — коллизия

Упрощённо хеш-таблица работает так:

  1. вычисляет hash(key);
  2. превращает хеш в номер ячейки, например остатком от деления на размер таблицы;
  3. идёт в эту ячейку и сравнивает ключ с тем, что там лежит.

Если два разных ключа получили один номер — это коллизия. Таблица не считает их одинаковыми: она хранит сами ключи и проверяет равенство. В Python конфликты разрешаются открытой адресацией — таблица ищет следующую подходящую ячейку; в других реализациях часто используют цепочки из узлов. Когда таблица заполняется, Python увеличивает её и пересчитывает индексы — это перехеширование.

Хеш строк в Python рандомизируется при запуске, чтобы нельзя было заранее подобрать много коллизий. Поэтому конкретное число hash("кот") может отличаться между запусками; важно лишь, что одинаковые ключи в одном запуске дают одинаковый хеш.

Общая цена у всех хеш-структур одна: в среднем O(1), но при большом числе коллизий — в худшем случае O(n); порядок не заменяет сортировку; изменяемые объекты нельзя делать ключами. Зато там, где нужны быстрые проверки и доступ по ключу, set и dict обычно выигрывают у списка.

Компромисс вместо идеала

Не существует структуры, быстрой во всём: массив проигрывает во вставке, список — в доступе, хеш-таблица — в упорядоченности.

Практический приём — выбрать структуру под главную операцию и не оптимизировать редкие случаи.

Структура определяет алгоритм

Многие «медленные» задачи ускоряются не оптимизацией кода, а сменой структуры: словарь вместо списка, куча вместо сортировки на каждом шаге.
